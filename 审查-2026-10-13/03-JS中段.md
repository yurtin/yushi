### [🔴] 年份滑轮能一路拖到 1970，热力图会一次渲染两万多个格子（预计真机卡死）

- 位置：`鱼事.html:9729`（年份列表 `for (let y = 1970; ...)`）、`9619-9639`（`stGoMonth` 的 `stBack`）、`9394-9408`（`statMonthList`）、`9424-9429`（逐日造格）
- 症状：在「连续打勾」子页点中间那行「2026年」→ 年月滑轮弹窗 → 滚到 **1970** → 关闭。页面随即重画**从 1968-11 到 2026-12 的每一个日期**：约 **21,000 个 `.st-cell`**、约 **1.8 MB innerHTML**。之后每一次 `refresh()`（在子页里勾选一条、切页再回来）都会把这 21,000 个格子重建一遍；`stPaintYm` 每换一个月还要 `querySelectorAll('.st-cell')` 全量扫一遍改 class。
- 证据：
  - `stGoMonth`：`need = (t.getFullYear() - y) * 12 + (t.getMonth() + 1 - m) + 2; if (need > stBack) stBack = need;` —— y=1970、m=1 时 `need = 684`，且 `stBack` **只增不减**。
  - `statMonthList`：`first = new Date(t.getFullYear(), t.getMonth() - 11 - stBack, 1)`，`floor = new Date(..., t.getMonth() - 59 - stBack, 1)` —— 起点与地板**都**跟着 `stBack` 往后退，于是"最多往回 60 个月"这条注释里的上限当场失效。
  - 渲染循环：`for (let d = new Date(first); d <= cap; d.setDate(d.getDate() + 1)) cells += '<span class="st-cell" ...>'` —— 1968-11-01 → 2026-12-31 = **21,244 天**，每格 HTML ≈ 85 字节。
  - 触发入口是产品**自己造的门**：`openYmSheet` 的年份轮第一项就是 1970（`for (let y = 1970; y <= t.getFullYear(); y++)`），滚轮一次能滚到。
- 后果：中低端安卓机上这一下大概率是几秒到十几秒白屏/无响应（Android WebView 无 adb 未真机计时；**DOM 规模是算出来的确定值**，不是猜的）。同日再有勾选操作会叠加卡顿。
- 修法：① `stBack = Math.min(stBack, 48)` 之类的**预算夹紧**，把"往前无限"限制在 60 个月以内；② 年份轮的起始年改成"最早有记录的年"或按 60 个月倒推出来的年，而不是写死 1970；③ 更彻底的做法是按需窗口渲染（只渲染当前月 ±12 个月，滚到边界再补）。三者取一即可，①最小。

### [🟡] `originRowHTML` 把 `rvd()` 拼进了 class 属性里 → `--delay` 静默失效 + 产出非法属性

- 位置：`鱼事.html:9275-9283`（`const attrs = \`${rv()}${rvd(60)}\``；`class="stat-origin${attrs}"`，空态那支同病）
- 症状：统计子页那行「短期 / 长期 / 循环」本该比标题栏晚 60ms 淡入，实际与标题同时出现；渲染出的 HTML 是
  `class="stat-origin reveal-on-scroll style="--delay:60ms""`。
- 证据：
  - `rv()` → `" reveal-on-scroll"`，`rvd(60)` → `" style=\"--delay:60ms\""`（6714-6715），两者**一起**塞进了 `class="..."` 的引号里。HTML 解析器的属性值在下一个引号处就结束，于是 `class` 只到 `...style=`，`--delay` 变成一个名字很怪的垃圾属性，**不是内联样式**。
  - `.reveal-on-scroll` 靠 `animation-delay:var(--delay,0ms)`（521 行）取值，所以 60ms 错峰整个丢掉。
  - 同一文件里正确的写法是把 `${rvd()}` 放在 class 属性**外面**：8271 `<div class="idea-toolbar${rv()}"${rvd(30)}>`、8343、8391、9891 都是这么写的 —— 这一处是全站唯一的例外。
  - 为什么测试没拦住：`_ref/_0e-regress.mjs:122-123` 把 `rv/rvd` 桩成 `()=>''`（注释 434 行自己写明"rvd 是桩，渲染不出 --delay"），而 `_ref/_0g-dom.mjs:303,312` 只断言 `classList.contains('reveal-on-scroll')` —— 这条**仍然为真**，从没量过这一行的 `--delay`。
- 后果：与 0G 第三轮那个 `soloop`（class 少一个空格）同族的静默失效；这次不歪样式，歪的是"这一行到底有没有按时入场"。
- 修法：`<div class="stat-origin${rv()}"${rvd(60)}>`，空态那支 `class="stat-origin empty${rv()}"${rvd(60)}`。顺手在 `_0g-dom` 的 [5] 加一条"这一行的 `--delay` 非空"。

### [🟢] 撤销用"整表快照"而不是"精确还原"，会把撤销窗口内别的改动一起回退

- 位置：`鱼事.html:8824-8827`（批量生长撤销）、`8997-8999`（清空示例撤销）
- 症状：`const keep = S.items.filter(x => made.indexOf(x) < 0);` 在 `toast()` **之前**算好并被回调闭包捕获；撤销时 `S.items = keep` 整表赋值。于是这个窗口（提示条存活期）里**新加的**条目会随撤销一起消失，窗口里**删掉的**条目会复活。

### [🟢] 渲染性能：`renderIdeas` 的祖先回填是 O(n²)

- 位置：`鱼事.html:8247-8258`
- 症状：`for (const i of all.slice()) { while (cur.parent && ...) { if (!all.some(x => x.id === p.id)) all.push(p); ... } }` —— 每条想法 × 每一级祖先都**扫一遍整个数组**。500 条深链想法 ≈ 500 × 深度 × 500 次比较，全在首屏渲染路径上。
- 证据：`all.some(...)` 位于两层循环的最内层；同一函数后面 `live`/`used` 还各自再走一遍祖先链。
- 修法：先建 `const have = new Set(all.map(x => x.id))`，改成 `if (!have.has(p.id)){ all.push(p); have.add(p.id); }`。
- 补充：同类问题在 `renderZoneBody` 已被 `_verify-a11y.mjs` 的**源码级断言**看住（禁止渲染路径里出现 `S.items.filter(...)`），但 `all.some(...)` 这条形状绕过了那条断言。

### [🟢] 滚动处理里每帧读 `scrollHeight`

- 症状：每次 scroll 事件都读一次 `document.documentElement.scrollHeight`（在被 F1 放大的那页是两万个格子的整篇布局读数）、一次 `getElementById`、一次 `classList` 读写。passive 监听，但读数可能触发一次布局结算。

| 术语 | 一句话人话 |
|---|---|
| `innerHTML` | 把一段字符串当网页代码塞进页面；里面带 `<` 或引号的内容没处理就会跑起来（就是 XSS） |
| `esc()` | 项目里那个"把危险字符换成安全字符"的函数，拼 `innerHTML` 前必须过一遍 |
| 事件委托 | 不给每个按钮单独挂点击，只在外面挂一个、靠"点到了谁"分辨 —— 分辨的先后顺序写错就会点错 |
| DOM 规模 / DOM 节点 | 页面上真实存在的小方块数量；两万个格子就是两万个要浏览器算一遍对象的方块 |
| 布局抖动（强制回流） | 改完样式又马上读尺寸，浏览器被迫反复重算整页排版，滚动就会一卡一卡 |
| O(n²) | 数据多一倍、耗时多四倍的那种写法（每个条目都要把所有条目扫一遍） |
| 静默失效 | 代码没报错、看着也执行了，但答应用户的效果其实没发生（最难查的一类） |
| 整表快照撤销 | 撤销时把整份数据换回"动作发生前的样子"，而不是只精确撤掉那一步 —— 中间别人的改动会被一起吞掉 |
