## 二、已知的刻意设计（**不要报成缺陷**，报了就是假阳性）

1. AI 请求失败/超时/关着时**回落到本地解析**，不生成假数据 —— 这是产品红线。
2. 大量 `innerHTML` 字符串拼接是本项目既有形态（不是 React，无虚拟 DOM）。**但**：凡是「用户原话 / AI 返回的 title·corrected·steps / 备份文件内容 / 他人分享内容」被直接拼进 `innerHTML` 而**没有走 `esc()` 或等价转义**，必须报 XSS。
3. 全局函数多、模块靠注释分区（`/* ---- 标签词典`、`/* ===== 应用层`）—— 结构本身不算缺陷；但**同名函数被定义两次**（后者静默覆盖前者）是本项目的历史事故类型，发现即报 🔴。
4. 单文件、无构建、无打包器是既定形态。
5. `_ref/` 下的探针脚本、`shots-*`、`_tmp_*.txt`、`_remi/`、历史 `.apk` 都属于工作噪音，不审（除非你负责构建/测试那一块）。

## 三、工具与规则

### 3.1 OCR（open-code-review，委托模式）

```powershell
cd 'D:\DSH\工作区\待办集'
& 'D:\DSH\工作区\ai相关\_fetch\ocr\ocr.cmd' delegate preview                 # 工作区 diff 口径
& 'D:\DSH\工作区\ai相关\_fetch\ocr\ocr.cmd' delegate preview --from <旧commit> --to HEAD
& 'D:\DSH\工作区\ai相关\_fetch\ocr\ocr.cmd' delegate rule <文件> [文件...]    # 命中哪套规则
```
委托模式**不联网、代码不出本机**；评审意见由你（模型）按规则产出。

`鱼事.html` 因为扩展名是 `.html`，只命中 `default` 通用包；其内联 JS 的规则包（把脚本抽成 `.js` 后 `rules check` 实测命中 `**/*.{ts,js,tsx,jsx,mjs,cjs}`）原文摘录：

- **XSS 防护**：确认用户输入被正确转义。
- **innerHTML 安全**：禁止把用户输入直接插进 `innerHTML`；用 `textContent` 或做 XSS 防护。
- **代码注入**：禁止 `eval()`、`Function()` 构造器、`setTimeout/setInterval` 的字符串参数形式。
- **危险方法**：禁止 `document.write()`。
- **敏感信息**：检查 API key / 敏感数据是否暴露。
- **原型链安全**：禁止改原生对象原型（`Array.prototype` / `Object.prototype`）。
- **Dead Code**：永远走不到的分支、声明后未读的变量、大段注释掉的代码。
- **重复代码**：可抽取的公共逻辑。
- **硬编码**：业务相关硬编码字符串（尤其 URL 路径与业务数字）；简单 UI 文案可放宽。
- **`var` 禁止**；**`==` / `!=` 禁止**（用 `===` / `!==`）；**嵌套三元禁止**。
- **空值检查**：取值/解构前做空值判断。
- **异步**：异步函数必须有错误处理与用户可读的错误提示；优先 `async/await`，禁止回调地狱；独立异步用 `Promise.all`。
- **React 规则**（本项目不用 React）：不适用，忽略。
- **Correctness/Security/Performance/Maintainability/Testing**（default 通用包）：逻辑正确性、边界条件、异常处理；并发安全；SQL 注入/XSS、敏感信息、鉴权完整性；N+1、无谓循环、资源释放；可维护性。
