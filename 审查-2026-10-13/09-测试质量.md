## 一、T1 Test Obscurity（测试晦涩）

### [🟡] 12 个主力回归脚本把「项目绝对路径」写死成默认值，测试的前置条件在测试体里看不见

- 位置：`_ref/_0a-regress.mjs:14`、`_0b-regress.mjs:14`、`_0c-regress.mjs:12`、`_0e-regress.mjs:14`、`_0f-regress.mjs:10`、`_1-regress.mjs:17`、`_2a-regress.mjs:21`、`_2c-regress.mjs:12`、`_4a-regress.mjs:17`、`_4c-regress.mjs:19`、`_7b-regress.mjs:15`、`_parse-regress.mjs:4`
- 症状（Symptom）：12 个脚本的第一行有效代码都是
  `const FILE = process.argv[2] || 'D:/DSH/工作区/待办集/鱼事.html';`
  —— 被测对象（哪份 HTML、哪个副本）不是测试的显式参数，而是一个藏在文件顶端的常量。另有 50+ 个探针写 `const PROJ = 'D:/DSH/工作区/待办集'`。
- 证据：`_0a-regress.mjs:14`；`_ref/_7b-apkrun.mjs:33` 走的是「拿包内页面」这条路，是同族脚本里唯一把被测对象显式当参数的。
- 来源（Source）：Meszaros — *xUnit Test Patterns*，Mystery Guest (p.411)
- 后果（Consequence）：① 换机器/换盘符/换目录名 → 12 个脚本一起以「找不到鱼事.html 或断言全红」的方式死掉，报错还指不到真因；② 想用「HEAD 快照」做 A/B 对照（内存里记着的标准手法：`git show HEAD:鱼事.html > 临时文件` 再喂脚本）时，漏传 argv 就会静默拿当前工作副本比对，得出「没变化」的假结论 —— 这个坑在 0F 卡里真踩过。③ 读脚本的人必须翻到第 14 行才知道它在测什么文件。
- 修法（Remedy）：把 `_ref/` 下的 `ROOT`/`FILE` 全部换成 `path.resolve(import.meta.dirname, '..')`（`_0d-geom.mjs`、`_5d-dom.mjs`、`_0b-dom.mjs` 等 41 个 CDP 脚本已经这么写了，是现成范例），把「测哪份 HTML」收成 `--file=` 参数；`_parse-regress.mjs` 同时补进 git。

### [🟡] 断言标签写着「★」但失败信息为空，红的时候不知道期望值是什么

- 位置：`_ref/_0b-regress.mjs:218,220,321,324,387-389,402-403,414-417,436-439,462,492-498,511-512,610-618`；`_ref/_2a-regress.mjs:606-611,632,635,660`；`_ref/_5e-regress.mjs:380`
- 症状（Symptom）：`tOk(label, cond, detail)` 的第三个参数是可选 detail，但大量调用写成 `tOk('…', /…/.test(html))` 或 `tOk('…', cond, '')`。失败时输出只有
  `  FAIL ★ 提示词里不再有「想做的事」  →  `（箭头后面是空的）。
- 证据：`_5f-regress.mjs` 运行输出（本次实测）：
  `ok   ★ AI_IMAGE_SYS 里不含旧措辞「想做的事」  →  `
  —— 通过时看不出测的是什么值，失败时同样看不出期望值。对比 `_0a-regress.mjs:21` 的 `t()` 会把 `got` 与 `期望 want` 都打出来，信息量差一个数量级。
- 来源（Source）：Meszaros — *xUnit Test Patterns*，Assertion Roulette (p.224)；Osherove — *The Art of Unit Testing*，断言消息约定
- 后果（Consequence）：源码级红线红掉时，输出只告诉你「这条没了」，不告诉你当前值是什么、差在哪。修复成本从「看一眼输出」变成「打开脚本读正则，再 grep 源文件」。
- 修法（Remedy）：给 `tOk` 加一条约定并批量补齐 detail（源码级断言一律传当前命中的片段，如 `(html.match(/…/)||['无'])[0]`）；更彻底的做法是让 `tOk` 在失败时自动把被断言的字符串打出来。

## 二、T2 Test Brittleness（测试脆性）

> **这是本项目最严重的一类。** 记忆里 0E / 0F / 5D / 5F / 5G / 5I / 6B / 7D / 7.2 一共 9 轮把「脚本漂移」当成常规工作项登记，每轮 3–21 条断言成批红、全部按「改断言不改代码」处置。这正是 T2 严重度指南里的 Critical 判据。

### [🔴] 断言在被测源码的**字面形状**上：重构不改行为也会让它成批红

- 位置（源码级断言 218 处 / 26 个脚本，代表：
  `_0a-regress.mjs:284-289`、`_0b-regress.mjs:321-324,353-355,387-389,402-403,414-417,436-439,462-498,610-618`、`_5i-regress.mjs:366-374,394-400,499-504`、`_6a-regress.mjs:467-472`、`_2b-regress.mjs:230-240`、`_2c-regress.mjs:329-346`）
- 症状（Symptom）：断言直接对 HTML 文本做正则，钉的是**写法**不是行为：

  | 脚本:行 | 断言原文 | 钉住的是什么 |
  |---|---|---|
  | `_0b-regress.mjs:353` | `/下面还有 '\s*\+\s*n\s*\+\s*' 项没做/` | 字符串拼接的**空格与加号位置** |
  | `_5h-regress.mjs:261` | `/卡片自己的 padding 一个字节不动/.test(html) && /卡片 padding 一个字节都不许动/.test(html)` | **代码注释的措辞** |
  | `_5e-regress.mjs:380` | `/★ 5E：加任何本地口语规则时，必须问一句/.test(html)` | **代码注释的存在** |
  | `_5i-regress.mjs:366-369` | `(html.match(/const SEED_LONG_MS = 400;/g)||[]).length` 必须 `=== 1` | 常量声明的**分号与空格** |
  | `_0a-regress.mjs:285` | `!/\.map\(renderTree\)/.test(html)` | 不许出现某个**调用写法** |
  | `_0b-regress.mjs:387-389` | `/autoDoneParent: false,/` + `/data-set="autoDoneParent"/` | 字段初始化行的**尾逗号** |
  | `_2b-regress.mjs:230` | `html.match(/const AI_UNDERSTAND_SYS =[\s\S]*?;\n/)[0]` 后逐字符比 | 提示词全文（这条是**有意的**缓存红线，见下方"不报"项） |
  | `_6b-regress.mjs:20` | `JSON.parse(_6b-baseline.json)` 后比 27 段处理逻辑逐字符 | 6.0.0 时刻的实现快照 |

- 证据：`_5h-regress.mjs:255-261` 整段的那个断言是
  ```js
  tOk('卡片自己的 padding 一个字节不动（折叠只在裁剪层解决）',
    /卡片自己的 padding 一个字节不动/.test(html) && /卡片 padding 一个字节都不许动/.test(html));
  ```
  改一个汉字、或者把注释挪一行，测试就红，而**产品行为一个字节没变**。历史记录印证：5H 卡把 `_5h-regress` 的这段写死之后，7.2 卡改 `zoneStep`→`zoneSlotStep` 时 `_7b-regress`/`_check-dupdef` 的 NAMES 就得跟着换（记忆「7.2.1–7.2.3 三条定案」§④）。
- 来源（Source）：Meszaros — *xUnit Test Patterns*，Eager Test (p.228) / Fragile Test；Hunt & Thomas — *The Pragmatic Programmer*，Ch.2 Orthogonality；Osherove — *The Art of Unit Testing*，implementation coupling
- 后果（Consequence）：**重构被测试惩罚。** 现存证据：0E 撤收纳区 → `_0b-regress` 95/9 + `_0b-dom` 79/23；5F 改按钮写法 → `_0b-regress`/`_0b-dom` 各 1 条；5G 摘焦点竖条 → `_3b-dom` 44→37；7D 改设置分组 → `_6b-regress`/`_6b-dom`/`_0d-geom`/`_5g-dom`/`_6c-dom`/`_verify-idea` 六处。团队已经把「改断言不改代码」制度化 —— 这句话本身就是"测试在阻碍变更"的自白。真实风险是：某次漂移太多，改断言的人顺手把**真缺陷**也一起"修"过去了（0C 那两条 `_0b-dom` 断言就与卡片要求正面冲突，属于该改的那一类，处理正确；但流程上没有护栏保证每次都判对）。
- 修法（Remedy）：
  1. **不要靠注释/空格做断言** —— 把那类断言删掉或换成行为断言（`_5h-regress.mjs:255-261` 应改判「`.zone.folded` 里没有任何 `padding` 声明」，即 `!/\.zone\.folded\{[^}]*padding/`，这个判据与措辞无关）。
  2. 对结构性契约（「只有一个 fetch 出口」）保留源码断言，但**只钉标识符，不钉空白与标点**：把 `/const SEED_LONG_MS = 400;/` 换成 `/\bSEED_LONG_MS\s*=\s*400\b/`。
  3. `_6b-baseline.json` 那套逐字符快照只该用于一次性迁移核验，迁移完成后应降级为「集合相等」断言（35 个 `data-*` / 15 个 id 保留，27 段处理逻辑取消）。

### [🔴] 测试驱动了产品形状：为让切片脚本能跑，产品里长期保留「转发口」与「不许新增函数」两条约束

- 位置：`_0a-regress.mjs:48-63`（extractFn）、`_0a-regress.mjs:71-80`（`appFnNames` + `new Function`）、`_1-regress.mjs:255`、`_3b-regress.mjs:44`、`_2c-regress.mjs:329-346`
- 症状（Symptom）：产品里存在**只因测试而存在**的结构：
  - `notifyFire` / `notifyFireMany` 两个转发口 —— 存在的唯一原因是「`addItem` 直接写 `syncNotify` 会让 `_0b-regress` 全部 ReferenceError」（见记忆「阶段1 提醒层定案」§②）。
  - 「护栏不许新增函数」—— 2C 卡把 7 个词的正则**内联进 `aiValidateItems`**，理由是「新全局函数在 `_2a-regress` 的隔离环境里会 ReferenceError」（记忆「2C 落点误判定案」§⑤）。
  - `_7b-regress` 的源码级要求：`renderZoneBody` 里不许直接读 `ANIM`，必须走 `rv()/rvd()` 转发口（记忆「7B 分区与 AI 落点定案」§⑥b）。
  - 4A 的辅助函数位置被规定死：「必须放解析层切片（标签词典→应用层之间），否则 `_0a/_0b/_1/_2a/_2b/_3a` 按名取不到」（记忆「4A 重复模型升级定案」§④）。
- 证据：`_0a-regress.mjs:78-79`：
  ```js
  const app = new Function('S', 'PARENT_GUARD', pure + '\n' + appSrc + '\n' +
    'return {parseSmart, sanitizeItems, sanitizeParents, ...};')(S, PARENT_GUARD);
  ```
  被测函数必须能在这个手工搭的隔离环境里跑起来 —— 环境的边界（哪些全局存在、函数必须落在哪一段）成了**产品的架构约束**。
- 来源（Source）：Feathers — *Working Effectively with Legacy Code*，Ch.3 Sensing and Separation（test-only production methods）
- 后果（Consequence）：① 产品代码里为了"能被切片"而保留了转发口这一层间接，增加了真实调用链的复杂度；② 新写代码的人必须知道「函数放哪一段、能不能建常量」这条隐形规矩，否则撞一片红 —— 这是纯正的测试引入的架构损伤；③ 反过来，一旦有人不知道这条规矩直接调 `syncNotify`，会一次性打红 100+ 条本来绿的断言，排查成本极高。
- 修法（Remedy）：把「隔离环境」本身变成产品侧承认的接缝。两个方向：
  **(a) 低成本**：在 `鱼事.html` 里显式声明一个 `window.__YUSHI_TEST__` 只读快照（把 `parseSmart`/`renderZoneBody` 等纯函数挂上去），CDP 脚本与 Node 脚本都从这个快照取，`extractFn` 退化为"取不到才回退切片"。这样"函数放哪一段"不再是约束。
  **(b) 大改造**：把解析层（约 4,000 行）实际拆成一个独立 `_shared/parse.js`，`鱼事.html` 用 `<script src>` 引它，Node 直接 `import`。见第六节。

### [🟡] 断言的正则里带着"当时那次事故"的痕迹，语义已过期但没人敢删

- 位置：`_5e-regress.mjs:375-377`、`_5h-regress.mjs:197-210`、`_5i-regress.mjs:366-369`、`_2c-regress.mjs:329-346`、`_7d-regress.mjs:40`（`grab()` 切片长度）
- 症状（Symptom）：断言标签里写着历史轮次（`★ 5E 修`、`★ 5H 修`、`★ 7C 修`），断言的**主体是那次修复的边界值**，而边界值本身会随产品演进改变。典型：`_5e-regress.mjs:264`
  ```js
  t('下午3点 开会 → 只有钟点 → zone=z_short（★ 7C 修：5E 登记时沉 z_long）', ...)
  ```
  —— 5E 登记的期望在 7C 被反转，于是断言文本里同时保留了两个时代的口径。
- 证据：`_7d-regress.mjs:40` 的 `grab()` 在 7A 卡里因为新加了一个 `const noteUI` 让 `AI_IMAGE_SYS` 的切片长度从 23939 掉到 11576 —— 一条**与 AI 图片提示词毫无关系**的新常量，打红了一条比提示词逐字符的断言（记忆「7A 长文本笔记定案」§⑦）。
- 来源（Source）：Meszaros — *xUnit Test Patterns*，Obsolete Test / Fragile Test
- 后果（Consequence）：断言文本为了携带历史而越写越长（`_5e-regress.mjs` 单文件 25KB / 109 条），新读者无法判断哪些边界是**现行产品契约**、哪些只是历史残影。删掉怕丢覆盖，留着怕假红。
- 修法（Remedy）：把「历史轮次」从**断言主体**移出去 —— 断言只表达当前契约，历史放在脚本顶部的变更记录注释里。给每条源码级红线加一行注释标明「这条钉的是哪个不变式，什么时候可以删」。

## 四、T4 Mock Abuse（模拟滥用）

> 本项目没有 mock 框架，但「桩」的形态极重：CDP 脚本用 `Page.addScriptToEvaluateOnNewDocument` 与 seed 注入把 `YuShiNative` 整个桥替换成记录器。评估结论：**这一类的用法基本是正确的** —— 桥桩是唯一能覆盖原生侧调用路径的手段，且断言落在「哪些 id 被排/被撤」这种可观测状态上，不是 `expect(mock).toHaveBeenCalled()` 式的自我循环。**只报下面两条。**

### [🟡] 桩桥的「不完整」会让整段断言静默变成空过

- 位置：`_5d-dom.mjs:43-53`（BRIDGE 桩）、`_1-notify.mjs:59`、`_5e-dom.mjs:45`、`_6b-dom.mjs:108`
- 症状（Symptom）：`_5d-dom.mjs` 的桥桩只声明了 6 个方法：
  ```js
  window.YuShiNative = { insets, isAvailable, notifySchedule, notifyCancel, notifyPermState, openNotifySettings };
  ```
  产品侧 `MainActivity` 实际暴露的桥方法远多于此（`notifyExactState` / `notifyFullScreenState` / `openExactSettings` / `openBatterySettings` / `getLastFire` / `startRec` / `stopRec` / `pickImage` …）。页面代码对桥的调用大多带 `typeof b.x === 'function'` 守卫（这是产品的正确做法），于是**桩里缺的方法会让那条分支静默跳过，断言仍然绿**。
- 证据：`_5d-dom.mjs:47` `isAvailable: function(){ return 'false'; }` —— 一个恒返 `'false'` 的探针。任何依赖 `isAvailable() === 'true'` 的路径在这个脚本里永远走不到，而脚本不会报「我跳过了 X」。
- 来源（Source）：Osherove — *The Art of Unit Testing*，Incomplete Mock；Meszaros — *xUnit Test Patterns*，Hard-Coded Test Data (p.534)
- 后果（Consequence）：`_5d-dom.mjs` 名义上覆盖「删除的级联与撤销还原」，但它验的只是**页面在桥方法缺失时的降级行为**。真机上「删掉父任务后子任务闹钟是否真的撤了」这条断言并没有被它保护 —— 5D 卡自己就承认过这个 bug（`syncNotifyMany` 对已删 id 整批跳过 → 子任务闹钟原封不动）是靠**用户报障**发现的。
- 修法（Remedy）：桥桩改为**从产品侧清单反向生成** —— 在 `鱼事.html` 里维护 `const BRIDGE_METHODS = ['notifySchedule','notifyCancel',…]`（页面本来就该知道自己要什么），桩按它逐个建方法，并为每个方法记录「本次是否被调用」；脚本结束时打印一份「未被触及的桥方法」清单。任何**预期会走到**但从未被调用的方法都算失败。同时把 `isAvailable: ()=>'false'` 改成按用例参数化，别让整脚本都跑在降级分支上。

### [🟢] `_0g-contrast.mjs` 的对比度计算依赖手写的颜色解析器，解析器本身没有测试

- 位置：`_0g-contrast.mjs`（`_rgb` 解析）、`_0b-dom.mjs:604,741`、`_3b-dom.mjs:119-120`、`_6b-dom.mjs:403`、`_6d-shadow.mjs:78`
- 症状（Symptom）：`_rgb` 这一个 6 行函数在 5 个脚本里各有一份**互不相同**的实现，且曾因 Chrome 把 `color-mix()` 序列化成 `color(srgb 1 1 1 / 0.54)`（0–1 浮点而非 0–255）而系统性地量错，报出「对比度 2.67」的假缺陷（0F 卡记录，0G 才修对）。
- 证据：`_0b-dom.mjs:604` 与 `_0b-dom.mjs:741` 是同一个文件里的**两份** `_rgb`；`_6d-shadow.mjs:78` 是第三套（`match(/-?[\d.]+px/g)`）。三个版本对 `color(...)` 语法的处理不同。
- 来源（Source）：Osherove — *The Art of Unit Testing*，test helper 的完整性；Meszaros — *xUnit Test Patterns*，Test Code Duplication
- 后果（Consequence）：测颜色的脚本本身是未验证代码，量错时给出的是**假缺陷**（工时浪费一整轮）而不是假绿。这是本项目已实际发生过的损失。
- 修法（Remedy）：把 `_rgb`/`contrastRatio` 抽进 `_kit.mjs`，并给它写 6 条自测（`rgb(255,255,255)` / `color(srgb 1 1 1 / 0.54)` / `rgba(0,0,0,.5)` / 8 位 hex / 命名色 `transparent` / 非法输入返回 null）。这一条几乎零成本且立刻止血。

## 五、T5 Coverage Illusion（覆盖率幻觉）

### [🔴] 「31 个纯 Node 脚本全绿」这个信号覆盖的是**实现形状**，不是用户可见行为；而真浏览器那 41 个脚本没有一个是必跑的

- 位置：`审查-2026-10-13/regress-now.txt`（全绿证据）；`_5f-regress.mjs:248-259`（DOM 那批未展开）
- 症状（Symptom）：本次实测 31/31 全绿，但逐条看输出可以确认**绝大多数通过项是源码级断言**。以 `_0a-regress.mjs` 为例，62 条里最后 8 条全部是「全文件出现 N 次」型；`_check-dupdef.mjs` 481 条全部是「函数定义次数 == 1」；`_6a-regress.mjs` 283 条里 [C][D] 两段是 hint 计数与红线 grep。
- 证据：`regress-now.txt:60-61`
  ```
  === _check-dupdef.mjs exit=0
  ok   openNoteHelp  →  1 处定义 | … | 全部唯一定义，通过（481/481）
  ```
  481 条断言 = 「481 个函数名在文件里各出现 1 次」。这类断言的价值是真实的（它抓过同名重复定义事故），**但它不测任何用户行为**，而它占了纯 Node 断言总数的很大一块（481 / 约 2,900）。
- 来源（Source）：Google — *How Google Tests Software*，Ch.11 change vs line coverage；Feathers — *Working Effectively with Legacy Code*，Ch.1 “legacy code is code without tests”
- 后果（Consequence）：绿并不代表能用。三条可核实的证据：
  1. `_5f-regress.mjs:251-257` 把 `_verify-idea.mjs` / `_verify-mobile.mjs` 登记成"常规回归清单"成员，但**它对这两个文件只做 `fs.existsSync` + 「内容里含『鱼事.html』」两条检查，从不执行它们**：
     ```js
     const LEGACY = ['_verify-idea.mjs', '_verify-mobile.mjs'];
     const exists = fs.existsSync(p);
     const points = exists && /鱼事\.html/.test(fs.readFileSync(p, 'utf8'));
     tOk('清单里的 ' + n + ' 存在且指向 鱼事.html', exists && points, p);
     ```
     —— 于是"登记进清单"这件事，在自动化上等同于没登记。
  2. 而这 7 个 `_verify-*` 里的 6 个**根本没进 git**（见 T6），所以在新克隆的仓库里上面那两条 `existsSync` 断言会直接红 —— 连"文件存在"这层最弱的保护都成立不了。
  3. 有明确记录在 HEAD 上就是红的（且不在任何门禁里）：`_verify-scrollock.mjs`（`#m_raw` 为 null → 崩，5G 卡记录「在 HEAD 快照上同样崩」）、`_verify-time.mjs`（6A 卡记录「在 HEAD 上就 FAIL + 崩」）、`_verify-motion.mjs`（0D 卡记录「在 HEAD 上就是红的（3 FAIL + 抛异常）」）。
  也就是说：**名册上有的脚本红了没人管、有的脚本压根不在仓库里，而纯 Node 那 31 个绿着，于是"全绿"被当成结论。**

- 来源（Source）：Google — *How Google Tests Software*，70:20:10 与测试清单的集中管理；Meszaros — *xUnit Test Patterns*，Slow Tests (p.253)
- 后果（Consequence）：① 新同学 / 新会话接手时**跑不出完整回归** —— 拿不到 7 个未跟踪脚本，也找不到 runner；② 「全绿」的判定标准散落在某个会话的记忆里；③ 41 个 CDP 脚本不能并行，一次全量 DOM 回归是串行的分钟级等待，这直接导致「只跑纯 Node 那批」成为习惯（而纯 Node 那批恰好是源码级断言占多数的那批 —— 这就是 T5 那条"绿不代表能用"的机制成因）。
- 修法（Remedy）：
  1. 根目录加 `_ref/_suite.json` + `_ref/run-all.mjs`（Node，跨平台，`--node` / `--dom` / `--all` 三档），并写进 `README.md`。
  2. `.gitignore` 把 `_ref/` 的排除改成白名单式：`_ref/*` 排除、`!_ref/*.mjs` `!_ref/*.json` `!_ref/真机验收.md` 放行；截图目录单独排除。一次改完，以后新脚本自动进仓库。
  3. 端口从 `_suite.json` 按脚本名哈希分配（或 runner 起服务时动态取空闲端口，脚本读 `process.env.CDP_PORT`），取消硬编码复用。
  4. 把 152 个一次性探针（`_probe-*` / `_dbg-*` / `_shot*` / `_g12*~_g17*` / `_7f2-patch1~31`）移到 `_ref/_attic/` 并排除出白名单 —— 它们是历史工单的证据，不是回归资产。这一步能把「哪些是测试」这件事从 224 个文件缩到约 70 个。

### [🟡] 全套串行执行时间未知，且被端口碰撞逼成串行

- 位置：`_ref/*.mjs` 41 个 CDP 脚本（每个 `spawn` 一次 Chrome + `sleep(1400)` 起底 + 多次 `sleep(120~500)`）
- 症状（Symptom）：每个 CDP 脚本固定 `await sleep(1400)` 等页面就绪、`sleep(120~500)` 等动画；`_5i-dom.mjs` 40KB、`_verify-idea.mjs` 117KB 更是内含几十段等待。没有总耗时记录，也没有一次全量跑完的证据（`regress-now.txt` 只跑了纯 Node 那批）。
- 证据：`_5d-dom.mjs:93` `await sleep(1400);`；`_7b-dom.mjs:108` 的 `goto()` 也写死 1400ms；`_verify-motion.mjs` 404 行、`_verify-mobile.mjs` 56KB。
- 来源（Source）：Meszaros — *xUnit Test Patterns*，Slow Tests (p.253)
- 后果（Consequence）：**慢测导致不跑。** 本次审查的任务书原文就要求「不要跑 CDP/DOM 脚本（会占端口）」—— 这是一个外部约束，但结果与"套件太慢所以不跑"完全一样：真浏览器那 41 个脚本的实际新鲜度无人能证明。而这 41 个恰好是唯一能抓 CSS 层序 / 命中测试 / 弹层实底这类真缺陷的一批（7B 的 ⋯ 点不了就是它抓的）。
- 修法（Remedy）：先测再优化 —— 加 `--json` 让 `run-all.mjs` 输出每个脚本耗时；把 `sleep(1400)` 换成 `Page.loadEventFired` + `waitForFunction('window.S && document.readyState==="complete"')` 事件驱动等待（`_5d-dom.mjs:92` 已经有 readyState 轮询，把后面那个固定 1400ms 删掉即可）；端口按第 6.1 条动态化后，用 `Promise.all` 分批并发（Chrome 实例数 ≤ 4）。

### [🟡] 出包核验是静态契约检查，覆盖不到「包里的东西跑起来对不对」

- 位置：`_android/_tools/verify_apk.py`（30 项断言，全文 270 行）
- 症状（Symptom）：`verify_apk.py` 验的是**产物形状**：包名/版本/minSdk/权限集合恰好相等/签名/`resources.arsc` 对齐/`assets/www/index.html` 与工作区逐字节一致/模型文件未压缩。它验不了「装上去能不能用」。
- 证据：`verify_apk.py:147` `check('权限恰好为 ' + repr(sorted(EXPECT_PERMS)), got == EXPECT_PERMS, …)` —— 集合恰好相等，**任何一次有意加权限都必须同步改这里**（1 阶段与 4C 各绊过一次，记忆有记录）。这条本身设计正确（权限是安全红线），但它使「权限变更」和「测试」之间产生了强耦合：忘了改就出一条"看起来像产品 bug"的红。
- 来源（Source）：Feathers — *Working Effectively with Legacy Code*，Ch.13 Characterization Tests；Google — *How Google Tests Software*，产物验收 vs 行为验收的分层
- 后果（Consequence）：出包核验通过 == 「这个包是我想打的那个包」；它不等于「这个包能跑」。真正的运行验证（安装、启动、通知、语音）当前是零 —— 而 `verify_apk.py` 的绿灯很容易被当成后者。
- 修法（Remedy）：
  1. 保持 `verify_apk.py` 的定位，但把它在报告里的标题从「全部通过 ✓」改成明确的**「产物核验通过（不含运行验证）」**，避免误读 —— 一行文案改动，收益很高。
  2. 另建 `_android/_tools/smoke_device.py`（adb 驱动）：装包 → 启动 → 录一条语音 → 断网启动 → 触发一次提醒 → 卸载。有设备时才跑，`verify_apk.py` 顶部提示它的存在。
  3. 权限断言保留「恰好相等」，但让 `EXPECT_PERMS` 从 `AndroidManifest.xml` 派生（和 `VER_EXPECT` 已有的做法一致，`verify_apk.py:46-55`），消除手抄漂移。

## 七、量化：这些脚本之间重复了多少？抽一个 `_ref/_kit.mjs` 能省多少行？

实测（Node 统计 `_ref/*.mjs` 顶层 224 个文件，45,984 行）：

| 重复样板 | 份数 | 合计行数 | 单一真相源后 |
|---|---:|---:|---:|
| CDP 握手（`const CHROME` → `spawn` → `/json/list` 轮询 → WebSocket → `send`/`ev` → `Page.navigate`） | 41 | **1,515** | 1 份 ≈ 40 行 |
| `extractFn`（配对花括号提取器） | 34 | **554** | 1 份 16 行 |
| `t` / `tOk` / 结果打印 / `process.exit` | 26 | **234** | 1 份 9 行 |
| 本地 http server + seed 注入（`html.replace('</head>', …)`） | 56 | **~260** | 1 份 12 行 |
| 解析层切片常量 + `pure` 拼接 | 26 | **~90** | 1 份 6 行 |
| `localStorage` 桩（`mkStore()`） | 4 | **~60** | 1 份 14 行 |
| 颜色解析 `_rgb`（互不相同的实现） | 5 | **~35** | 1 份 8 行 |
| **合计（断言型脚本口径）** | — | **≈ 2,750 行** | **≈ 105 行** |

**结论：抽一个 `_ref/_kit.mjs`（约 105 行），可删除约 2,700 行重复样板，占 45,984 行的 5.9%；若把 152 个一次性探针里的 CDP 样板也算进去，上限约 5,800 行（12.6%）。**

但**省行数不是重点** —— 重点是这 2,700 行里包着当前唯一一份「怎么连 CDP」「怎么切源码」「怎么打结果」的实现。它们各自被复制 26–56 次，意味着：
- 这些实现里的 3 个已知缺陷（`extractFn` 不认正则字面量、`_rgb` 不认 `color()` 浮点、CDP 就绪等待写死 1400ms）在全部拷贝里同时存在；
- 一次修要改 34/41/56 处，实际结果是**没人改**，于是每个新脚本继续继承同样的坑（0G 的 `_rgb` 是第二份、6D 又抄了第三份）。

**建议的 `_kit.mjs` 导出面：**
```
loadHtml(file?)        // 默认 path.resolve(dirname,'..','鱼事.html')，支持 --file=
sliceParseLayer(html)  // 标签词典 → 应用层
extractFn(html,name)   // 修掉正则字面量缺陷
constNum(html,name)
mkStore()              // localStorage 桩
cdp(opts) → {send, ev, goto, shot, close}   // 起 Chrome + 连 WS + 就绪等待（事件驱动）+ 端口动态分配
report → {t, tOk, summary}                  // 统一计数、统一退出码、失败必带 got/期望
browserSeed(html, seed, {bridge})           // 注入种子 + 桥桩（桥方法从产品侧清单反向生成）
redLines(html, {fetch:1, notifyTimeOf:3, …})// 11 处重复的红线断言收成一处

```

## 术语速查表

| 术语 | 一句话人话 |
|---|---|
| Test Obscurity（测试晦涩） | 读测试读不出它在测什么、期望值是什么 |
| Test Brittleness（测试脆性） | 改代码写法（不改行为）测试就红 —— 测试在惩罚重构 |
| Test Duplication（测试重复） | 同一件事在多处各写一遍，漏改一处就假绿 |
| Mock Abuse（模拟滥用） | 桩搭得比被测逻辑还复杂，测的是桩自己 |
| Coverage Illusion（覆盖率幻觉） | 跑过了 ≠ 验过了；绿着的断言可能一条用户行为都没碰 |
| Architecture Mismatch（架构错配） | 测试的形状（数量、层级、速度）跟系统真实风险对不上 |
| 假绿 | 测试通过，但真实场景里是坏的 |
| 假红 | 测试失败，但真实场景里是好的（多由功能搬家引起） |
| 源码级断言 | 不跑代码，直接在 HTML 文本里 grep 字面量/数出现次数 |
| 断言鲁棒性（本报告的建议） | 只钉标识符与语义，不钉空格、标点、注释措辞 |
| 倒金字塔 | 慢的端到端测试比快的单元测试还多 |
| 特征测试（Characterization Test） | 先把"现在的行为"钉住，再动它（Feathers） |
