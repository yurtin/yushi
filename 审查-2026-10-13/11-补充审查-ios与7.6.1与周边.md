## 🔴 1. PWA 升级链上有"半成品部署"风险：`rmtree` 先删后建 + `sw.js` 预缓存是 all-or-nothing

- **位置**：`_ios/build_pwa.py:193-195`、`_ios/dist/sw.js:15-19`（生成自 `build_pwa.py:147-151`）
- **症状**：`build_pwa.py` 第一步 `shutil.rmtree(DIST)` 把上一份可用的发布目录整个删掉，然后依次生成 index / manifest / sw / 图标。图标那一步依赖 Pillow 与 `_android/_tools/make_icons.py`（`build_pwa.py:32` 直接 `import`）。只要它在 rmtree 之后抛异常，`dist/` 里就剩下一份**没有图标的半成品**。
  而 `sw.js` 的 install 是 `caches.open(CACHE).then(c => c.addAll(SHELL)).then(() => self.skipWaiting())` —— `addAll` 是**全有或全无**：SHELL 里任何一张图标 404，整条链 reject → **Service Worker 安装失败** → 浏览器继续用旧 SW → 用户**永远停在旧版本**，且页面不会有任何提示。
- **证据**：`addAll` 语义（MDN：任一 request 失败则整个 promise reject）；`SHELL` 硬编码 9 个文件名（`sw.js:3-13`）。
- **后果**：部署漏一张图 = iOS 用户端"In-App 更新完全失效"，且现象是"看起来正常、就是不更新"——最难排查的一类。
- **修法**：①`install` 改成逐个 add 并容忍缺失（`Promise.allSettled(SHELL.map(u => c.add(u)))`），`skipWaiting()` 不绑在缓存结果上；②`build_pwa.py` 改成"先生成到临时目录，全部成功后再替换 dist"（避免半成品），或至少在 rmtree 前检查 `make_icons` 可导入。

## 🔴 2. 同一个文件有两个写入者：`_ios/dist/sw.js` 同时被 `build_pwa.py` 与 `_ref/_sync-build.mjs` 改写

- **位置**：`_ios/build_pwa.py:133-178`（生成整个 sw.js）与 `_ref/_sync-build.mjs`（只改 `const CACHE` 一行，实测日志："已写入 sw.js CACHE=yushi-7.6.2"）
- **症状**：`sw.js` 头部写着"**自动生成，别手改（改 _ios/build_pwa.py）**"，但版本号同步链（每次发版都会跑）也会改它。两条链对同一个产物的认知不同：sync-build 认为"只注入版本号"，build_pwa 认为"我负责整份文件"。
- **证据**：本地 dist 里 `sw.js:2` 是 sync-build 写的版本号；而该文件其余 41 行只在跑 `build_pwa.py` 时才会被刷新。
- **后果**：改 `build_pwa.py` 里的缓存策略（比如修上面那条 🔴）后**只跑 sync-build 不生效**；反过来，只跑 build_pwa 会让 dist 的 `index.html` 退回旧版本号（因为 build_pwa 也从 `AndroidManifest.xml` 读版本，此时是同版本，但 `HEAD_BLOCK` 与 sync-build 的注入块会各写各的）。这是本项目已经反复踩过的"同一处真相源被两条链写"。
- **修法**：收口成一个入口——要么 sync-build 调 `build_pwa.write_sw(version)`，要么 sw.js 里的 CACHE 改成从 `index.html` 读（页面注册 SW 时把版本当 query 传进去），二选一，并把另一条链的写入删掉。

## 🟡 3. `sw.js` 的失败兜底把"任何请求失败"都返回 `index.html`

- **位置**：`_ios/dist/sw.js:40`
- **症状**：`fetch(req).catch(() => caches.match('index.html'))` —— 不只导航请求，图片、跨域 GET（例如设置页那个"检查更新"打 `api.github.com`）失败时**同样**拿到一份 HTML、且状态是 200。
- **后果**：调用方（`JSON.parse`、`res.ok` 判定）会拿到一个"成功但内容错"的响应；轻则更新检查静默失败，重则未来某个新功能把 HTML 当数据解析。android 壳那条链没这个问题（不经过 SW）。
- **修法**：只对 `req.mode === 'navigate'` 兜底；其余直接 `Response.error()`。

## 🟡 4. `sw.js` 对跨域 GET 也做 `caches.match`

- **位置**：`_ios/dist/sw.js:31`
- **症状**：写入侧已限同源（`sw.js:35`），读取侧没有；将来若把写入条件放宽（很自然的一步优化），历史上缓存的跨域响应就会被回放。
- **修法**：读取侧同样加同源判断，或统一在函数开头 `if (new URL(req.url).origin !== self.location.origin) return;`。

## 🟡 5. `manifest.webmanifest` 的 `version` 字段浏览器不认

- **位置**：`_ios/build_pwa.py:120`
- **症状**：`'version': version` 写进了 manifest；Web App Manifest 规范里**没有** `version` 这个成员（它不参与更新判定），更新判定完全靠 `sw.js` 的字节差异。
- **后果**：维护者可能以为"改了 version 就会让用户更新"——不会。无害但误导。
- **修法**：删掉该字段，或在旁边注释说明"这只是记录，不参与更新"。

## 🟡 6. `stMarks` 缓存没有失效机制（7.6.1 引入）

- **位置**：`鱼事.html:9622`（`let stMarks = []`）、唯一赋值点 `9565`（`statHeatWire` 的 rAF 内）、使用点 `9598 / 9643 / 9656 / 9698`
- **症状**：`stMarks` 存的是每个月的 `offsetTop / offsetHeight`，只在"重新渲染后走 statHeatWire"时重算。**窗口尺寸变化**（横竖屏、平板分屏、软键盘顶起视口、浏览器缩放）后格子尺寸变化，这张表整张作废。
- **后果**：居中定位与 30% 吸附按旧几何计算 → 表现是"跳转后没对准 / 滑一下被吸到别处"。Android 端 manifest 锁了 `portrait`（`AndroidManifest.xml`），所以真机竖屏下很难遇到；PWA/桌面浏览器与平板会。
- **修法**：加一个 `ResizeObserver` 盯 `#stHeat`（尺寸变就 `stMarks = []`），或在 `stHeatMarks` 里带一个几何指纹（`heat.clientWidth + 'x' + heat.scrollHeight`）自动失效。**未实测**（本轮只读，无真机），标"待确认复现条件"。

## 🟡 7. README 与事实不符：写着"零权限"，实际 7 条权限

- **位置**：`README.md:84`（`AndroidManifest.xml 清单：零权限 + 版本号`）
- **症状**：4B/4C/5A 起陆续加了 `POST_NOTIFICATIONS`、`RECEIVE_BOOT_COMPLETED`、`SCHEDULE_EXACT_ALARM`、`USE_FULL_SCREEN_INTENT`，加上原有的 `RECORD_AUDIO` / `VIBRATE` 与联网版的 `INTERNET`，当前是 **7 条**（构建日志实测）。
- **后果**：README 是维护者（包括未来的我）判断"权限口径"的第一入口；写"零权限"会让人以为权限变更都是 bug。
- **修法**：改成"零**敏感**权限：录音按需申请、通知按需申请、无存储/定位/通讯录；完整清单见 manifest"。

## 🟡 8. 7.6.1 的提交混入了不属于它的改动（过程问题）

- **位置**：提交 `f39538b`（标题"7.6.1 热力图：当前月居中显示"）
- **症状**：该提交的 `鱼事.html` diff 里同时包含 `★ 审查修复（2026-10-13）` 的 `load()` 坏档保护、分区主键 `zoneLongKey()/zoneShortKey()` 等改动 —— 那是本会话当时未提交的工作树内容，被另一会话的 `git commit` 一并扫了进去。
- **后果**：`git log` / `git blame` 无法回答"这一行是谁、为什么改的"；日后 `git bisect` 定位问题会把两类改动混在一起。（与本项目此前的 2C/4C、7B/6B、5.6.0 双包同型：**并发写同一文件 + 一次提交把别人的改动带走**。）
- **修法（流程，不改代码）**：同一时间只允许一个会话动 `鱼事.html`；提交前先 `git status --short` 核对自己的编辑范围。
