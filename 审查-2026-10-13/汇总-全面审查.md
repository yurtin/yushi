| 你听到的叫法 | 专业叫法 | 一句话人话 | 这次的实际产出 |

## 四、没修的部分，以及为什么

### A. 要动骨架（4 类，需要你点头）

| 项 | 现状 | 为什么我不擅自动 |
|---|---|---|
| **单文件 1.9 万行** | `parseSmart` 一个函数 705 行、点击委托 657 行 | 拆成多文件再打回单文件是**架构级改动**，测试脚本全部要跟着改，风险远大于收益，除非你打算长期继续加功能 |
| **三个渲染出口** | `refresh` / `statGo` / `refreshAfterChange`，历史上"漏了一个出口"造成过 3 次真事故（空白屏、焦点不同步、点选闪） | 收敛成一个出口要重排渲染时序，属于"做完要重新全量验收"的活 |
| **测试夹具反向支配产品代码** | 37 个脚本"切片 + `new Function`"跑生产函数，于是产品里长期保留 39 处 `typeof` 守卫、4 处转发口，甚至有一段注释写着「这里**不能改调**自己的真相源」 | 要根治得改测试的加载方式，等于重写测试基础设施 |
| **逾期口径抄了 5 份** | `itemDue()` 是唯一实现但**零调用**（死代码），5 处逐字符重复 | `_ref/_5g-regress.mjs:136` 把"5 份"写成了断言——**测试把复制固化了**，改代码必须先改断言 |

### B. 要你拍板（2 条产品决策）

1. **隐私文案与实际不符**：设置页写"只发标题"，实际最多发 40 条标题 + 原话。要么改文案，要么改实现。
2. **`allowBackup="false"` 的代价**：隐私更安全，但你**失去了系统云备份/换机迁移**这条能力（这正是我关它的原因）。

### C. 交给下一轮（低价值或需专项）

`zonePruneFolded()` 调用顺序（试改会打红 6B 的逐字符断言）、`importText` 行尾数字退化、钟点解析存在三套并存、`batchBarSync` 不刷新工具条计数、长文编辑器不随切页收起、`verify_apk.py --ai` 只读 argv、Android 侧 `nReq` 哈希碰撞 / `stopSherpa` 未 join 工作线程 / 响铃页标题长度 / snooze 硬编码 5 分钟、`_ref/` 下 115 个脚本未纳入版本控制（换机器"回归全绿"不可复现）。

## 六、术语速查表

| 术语 | 一句话人话 |
|---|---|
| OCR / open-code-review / delegate 模式 | 本机跑的代码评审工具；它挑文件、我下判断，代码不出本机 |
| brooks-lint | 用 12 本工程经典书的经验清单，查"代码结构的腐化风险" |
| 健康分 | 把代码质量/架构/技术债/测试四项加权成一个 0–100 的数（本次 68） |
| 上帝函数（god function） | 一个函数什么都干、长到几百行，改一处影响全局 |
| 技术债 | 为了当时快而欠下的改造账，越晚还越贵 |
| 回归（regression test） | 改完之后把以前所有检查重跑一遍，确认没弄坏旧功能 |
| 断言（assertion） | 测试里"必须成立"的一句话；断言写错了会出现"假绿"（其实是红的却没报） |
| 红线（源码级断言） | 直接检查源码文本的断言，例如"这个函数全文件只能出现一次" |
| 幂等（idempotent） | 同一个操作做两遍和做一遍结果一样（恢复备份、示例数据都要求幂等） |
| 对比度 / AA | 文字与背景的明暗差；AA 是国际无障碍最低线（正文 4.5:1） |
| sha256 | 文件的"指纹"，用来判断两个 APK 是不是同一个东西 |
| versionCode / versionName | 安卓内部版本号 / 显示给人看的版本号 |
| 回归出口（渲染出口） | 页面重画的入口；出口多了就会"有的地方刷新了、有的没刷新" |
